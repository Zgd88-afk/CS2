## 1. 项目是什么

这是清华大学 & 剑桥大学研究者 Tim Pearce、Jun Zhu 发表的学术论文
**《Counter-Strike Deathmatch with Large-Scale Behavioural Cloning》** 的官方代码：

- 发表于 IEEE CoG 2022，获 **最佳论文奖**；另在 NeurIPS 2021 Offline RL Workshop 展示
- 论文：[ArXiv 2104.04258](https://arxiv.org/abs/2104.04258)
- 4 分钟介绍视频：https://youtu.be/rnz3lmfSHv0
- 实战演示视频：https://youtu.be/KTY7UhjIMm4

**它做了什么：** 用"行为克隆"（Behavioural Cloning，即模仿学习）方法，让神经网络观看大量
CS:GO 死斗模式（Deathmatch）第一人称游戏录像（画面 + 对应键鼠操作），学会直接从游戏画面
端到端地预测操作，最终像真人一样在 dust2 等地图上打 bot / 死斗：移动、瞄准、开枪、换弹。

**它不是什么：**

- ❌ 不是强化学习智能体（主体是模仿学习，只是额外训了一个 critic 价值头）
- ❌ 不是自瞄/透视外挂（不读敌人坐标，只看屏幕画面，凭"手感"射击）
- ❌ 不是开箱即用的产品（学术论文代码，路径硬编码、依赖版本老旧，需要自己动手改）

## 2. 核心原理：30 秒看懂

整个系统就是一个"看屏幕 → 按键鼠"的循环，以 **16 FPS** 运行：

```
每 1/16 秒：
┌─────────────┐    ┌──────────────────┐    ┌──────────────┐
│ 截取 CS:GO   │ →  │ 神经网络前向传播   │ →  │ 模拟键鼠操作   │ ─┐
│ 窗口截图     │    │ (EfficientNetB0  │    │ WASD/鼠标移动 │  │
│ 824×498 裁剪 │    │  + ConvLSTM)     │    │ /左键开枪     │  │
└─────────────┘    └──────────────────┘    └──────────────┘  │
        ↑────────────────── 循环 ←───────────────────────────┘
```

**训练方式（行为克隆）：** 从网上服务器" spectator 模式"录制高手对局 —— 每一帧保存
（截图 + 该帧的元数据），再用"逆动力学模型"从元数据反推出玩家当时的键鼠动作，
得到 (画面 → 动作) 配对样本，共约 5500 个文件 / 约 700GB。然后监督学习训练网络：
输入连续 96 帧画面，输出该时刻的动作。

**动作怎么表示（关键设计）：** 鼠标移动不是回归连续值，而是**离散化为若干档位**
（X 轴 23 档、Y 轴 15 档），键盘 11 个键 + 鼠标左右键用 sigmoid 多标签表示。
所以模型输出是一个 52 维向量（详见[第 9 节](#9-模型结构与动作空间技术细节)）。

**为什么需要 LSTM：** 单帧画面无法判断"正在扫射还是刚开第一枪"、"准星该往哪甩"，
所以用 ConvLSTM 记忆最近 96 帧（约 6 秒）的时序信息。

## 3. 仓库文件地图

### 3.1 全局配置与底层模块

| 文件 | 作用 | 你需要改它吗 |
|---|---|---|
| `config.py` | **全局参数中心**：帧率 `loop_fps=16`、图像尺寸 `(150,280)`、游戏分辨率 `(1024,768)`、LSTM 步数 `N_TIMESTEPS=96`、鼠标离散档位表、动作↔onehot 转换函数、模型存取函数 | 一般不改，调参时看这里 |
| `screen_input.py` | 截屏模块：win32 BitBlt 抓窗口 → 裁掉上下各 135px、左右各 100px → 缩放到 150×280 | ✅ 可直接运行它测试截屏 |
| `key_input.py` | 读取键盘/鼠标当前状态（GetAsyncKeyState），用于"按 Q 退出"等 | 不改 |
| `key_output.py` | **模拟键鼠输出**：DirectInput 扫描码 + SendInput 发按键/点击，`set_pos()` 发绝对坐标鼠标移动 | 不改 |
| `meta_utils.py` | ① 读游戏内存（ReadProcessMemory）② GSI 游戏状态服务的 HTTP 服务器（localhost:3000）③ 从 hazedumper 更新内存偏移 | 若配 GSI，需改 `MYTOKENHERE` |
| `dm_hazedumper_offsets.py` | CS:GO 内存偏移量表（客户端结构体地址），由上面脚本自动从 [frk1/hazedumper](https://github.com/frk1/hazedumper) 更新 | 不改 |

### 3.2 流水线脚本（按使用顺序）

| 顺序 | 文件 | 作用 |
|---|---|---|
| ① 录制 | `dm_record_data.py` | **旁观录制**：在服务器观战最高分玩家，每帧存 (截图+元数据)，每 1000 帧存一个 `.npy` |
| ① 录制 | `dm_record_data_me_wasd.py` | **本人亲自玩录制**：动作直接从键盘读取（需改用 T/F/G/H 代替 WASD，U 代替 R，M 代替空格），数据更干净 |
| ② 补标注 | `dm_infer_actions.py` | "逆动力学模型"：从元数据（视角变化、速度变化）反推每帧的键鼠动作，追加进 `.npy`；同时输出数据质量统计 |
| ③ 转格式 | `dm_pretrain_process.py` | 把 `.npy` 转成训练用 `.hdf5`（画面 + onehot 动作标签），支持快速随机读取 |
| ④ 可选 | `tools_extract_metaadata.py` | 把元数据从 `.npy` 里抽出来存成小文件（文件名有个拼写小瑕疵） |
| ⑤ 训练 | `dm_train_model.py` | **训练主脚本**：EfficientNetB0 + ConvLSTM，自定义多任务损失，数据增强 |
| ⑥ 转换 | `tools_create_stateful.py` | 把训练版模型克隆成"stateful"推理版（Keras 的 LSTM 有 stateful/stateless 两种模式，测试时必须用 stateful，否则每帧都重置记忆） |
| ⑦ 部署 | `dm_run_agent.py` | **运行智能体**：加载模型 → 16fps 截屏推理 → 模拟键鼠操作游戏 |

### 3.3 辅助工具与其他

| 文件 | 作用 |
|---|---|
| `tools_dataset_inspect.py` | 打开 `.hdf5` / `.npy` 数据集，快速查看内容 |
| `tools_view_save_egs.py` | 可视化连续帧序列，可叠加动作标注，可导出 PNG |
| `tools_dataset_stats.py` | 统计大数据集的动作分布等（论文附录 A 的图） |
| `tools_map_coverage_analysis.py` | 分析智能体/数据集在地图上的活动范围，计算 EMD 距离 |
| `console_csgo_setup.txt` | **CS:GO 控制台命令合集**：搭建离线死斗（简单/中等 bot）、aim 练枪图 |
| `e2e.yml` | Conda 环境定义文件（Python 3.7 + TensorFlow 2.3.0 全套依赖） |
| `NN_overview.png` / `intro_fig_dm.png` | 网络结构图 / 论文示意图 |
| `gif_data_01.gif` / `gif_gameplay_01.gif` | 训练数据示例 / 智能体实机演示动图 |

## 4. 准备工作

### 4.1 硬件与系统要求

| 用途 | 系统 | 硬件要求 |
|---|---|---|
| 运行智能体（推理） | **Windows**（必须，依赖 win32 API + SendInput 模拟键鼠） | 需要一块 **CUDA 显卡**。要在 16fps 内完成 EfficientNetB0+ConvLSTM 前向传播，GPU 太慢会导致操作延迟、智能体变菜 |
| 录制数据 | Windows | 同上，另需能流畅跑 CS:GO |
| 训练模型 | 作者用 **Linux**（脚本里是多 GPU `MirroredStrategy`，单卡 Windows 也能改着跑） | 大显存 GPU；数据集很大（完整版 700GB） |

### 4.2 Python 环境

原作者环境（**版本必须严格对齐，否则大概率报错或行为异常**）：

```
Python 3.6.9（conda 环境文件里是 3.7.15）
tensorflow 2.3.0    （注意：2.4.x 加载模型会产生不同预测结果！）
tensorflow.keras 2.4.0
h5py 2.10.0
numpy 1.18.5
opencv (cv2) 4.4.0
scipy 1.4.1
pywin32, pymem, mss, matplotlib, requests   （Windows 交互所需）
```

最省事的办法是用仓库自带的 conda 环境文件：

```bash
conda env create -f e2e.yml
conda activate e2e
```

> ⚠️ 新版 Python/TF（如 Python 3.10 + TF 2.12）**跑不起来**这套 2021 年的代码。
> 请勿尝试"升级修复"，直接用旧环境。有用户反馈 Python 3.9 + TF 2.4.5 会得到不同预测结果。

### 4.3 CS:GO 设置（重要！训练数据是在这些设置下录的）

模型看到的画面和它学到的鼠标灵敏度绑定，**游戏设置不匹配 = 智能体基本失灵**。
以下来自 `README.md` 排错章节（论文附录 E 有完整记录）：

**必须一致的设置：**

- 分辨率：**1024×768，4:3，窗口化**（不是全屏！截屏模块按窗口工作）
- 鼠标灵敏度：**2.50**
- 鼠标原始输入（Raw Input）：**关**
- 鼠标反转、鼠标加速：**关**
- 准星：经典静态，绿色 RGB(46,250,42)，长度 4.3、粗细 1.8、间隙 2.0，无外框无中心点
  （或直接用准星代码：`CSGO-UKcZG-QN8eW-WQMvd-NX6xr-RPqRP`）
- 画质：全部**最低**；Boost Player Contrast 开启；MSAA 2x
- HUD：边缘位置拉满、缩放 0.56、雷达 0.80
- "清除弹痕"（Clear Decals）绑定到 **n** 键（代码每 5 秒自动按一次 n）

**建议一致的设置（viewmodel，影响画面但次要）：**

```
cl_righthand 1; viewmodel_offset_x 1; viewmodel_offset_y 1; viewmodel_offset_z -1
viewmodel_fov 60; cl_bobamt_lat 0.33; cl_bobamt_vert 0.14; cl_bobcycle 0.98
cl_viewmodel_shift_left_amt 1.5; cl_viewmodel_shift_right_amt 0.75
```

### 4.4 游戏版本问题（2026 年重要提示）

本项目基于 **CS:GO 原版**（作者使用 1.37.7.0 ~ 1.38.0.1），而 CS:GO 已于 2023 年 9 月被 CS2 取代。
今天想跑通本项目：

1. 在 Steam 库中右键 **Counter-Strike 2 → 属性 → 测试版**，选择 **`csgo_legacy`** 分支，
   即可下载旧版 CS:GO（Valve 官方保留的 legacy 版本；2026 年起旧版还可能以独立应用形式提供）。
2. dust2 地图在 1.38.0.2 有小改动，追求完全一致可从创意工坊下载旧版地图：
   https://steamcommunity.com/sharedfiles/filedetails/?id=2606435621
3. 内存偏移（hazedumper）已冻结在 CS:GO 最终版本，与 legacy 版本匹配，**录制脚本开头的自动更新偏移仍可用**。

### 4.5 （可选）配置 GSI 游戏状态集成

**只在两种情况下需要**：① 录制数据；② 运行智能体时想统计击杀/死亡分数（`IS_GSI=True`）。
**只跑路线 A 且不在乎分数统计 → 跳过本节**（`dm_run_agent.py` 默认 `IS_GSI=False` 可运行）。

GSI（Game State Integration）是 CS:GO 官方提供的游戏状态推送机制，游戏会把血量、击杀数、
武器等以 HTTP POST 发到你本机的一个端口。配置方法：

1. 在 `Counter-Strike Global Offensive/csgo/cfg/` 下新建文件
   `gamestate_integration_agent.cfg`，内容如下（token 必须与 `meta_utils.py` 里的
   `MYTOKENHERE` 一致，或把代码里的 token 改成你自己定义的）：

   ```
   "Counter-Strike: Global Offensive"
   {
       "uri" "http://localhost:3000"
       "timeout" "5.0"
       "auth"
       {
           "token" "MYTOKENHERE"
       }
       "data"
       {
           "provider"            "1"
           "map"                 "1"
           "round"               "1"
           "player_id"           "1"
           "player_state"        "1"
           "player_weapons"      "1"
           "match_stats"         "1"
       }
   }
   ```

2. 重启游戏使配置生效。
3. 详细原理参考社区教程：
   https://www.reddit.com/r/GlobalOffensive/comments/cjhcpy/game_state_integration_a_very_large_and_indepth/

## 5. 路线 A：运行官方预训练模型（最快见效）

**目标：** 下载作者训好的模型，让 AI 在离线死斗里自己打 bot。全程约 30 分钟。

### 第 1 步：下载模型

到 HuggingFace 下载（位于仓库的 `trained_models/` 目录）：

> https://huggingface.co/datasets/TeaPearce/CounterStrike_Deathmatch/tree/main

四个可选模型（都分 **non-stateful**（训练用）和 **stateful**（推理用）两个版本，**运行要下 stateful**）：

| 模型名 | 说明 |
|---|---|
| `ak47_sub_55k_drop_d4_dmexpert_28` | ⭐ **推荐**：预训练 + 死斗专家数据微调，作者最强死斗 agent |
| `ak47_sub_55k_drop_d4` | 仅预训练版 |
| `ak47_sub_55k_drop_d4_aimexpertv2_60` | 预训练 + aim 练枪图微调（枪法更凶） |
| `July_remoterun7_g9_4k_n32_recipe_ton96__e14` | 全量数据集预训练 |

每个模型是一对文件：`<模型名>_stateful.json`（网络结构）+ `<模型名>_stateful.h5`（权重）。

### 第 2 步：放置模型

在仓库根目录建一个 `model` 文件夹，把下载的 stateful 两个文件放进去：

```
D:\ZCode\CSGO\v1\
├── model\
│   ├── ak47_sub_55k_drop_d4_dmexpert_28_stateful.json
│   └── ak47_sub_55k_drop_d4_dmexpert_28_stateful.h5
├── dm_run_agent.py
└── ...
```

> 原因：`dm_run_agent.py` 第 72 行 `model_save_dir = os.path.join(os.getcwd(),'model')`，
> 从**运行脚本时所在目录**下的 `model/` 加载。你也可以改这行指向别的路径。

### 第 3 步：选择模型

打开 `dm_run_agent.py`，确认第 68 行的模型名与你下载的一致：

```python
model_names = ['ak47_sub_55k_drop_d4_dmexpert_28']
```

### 第 4 步：搭建游戏环境

1. 启动旧版 CS:GO，进入
   **主菜单 → 练习模式（Practice With Bots）→ 死斗（Deathmatch）→ 经典模式 → Dust II → 简单 bot**
2. 手动加入 T 阵营，购买 AK47
3. **开启开发者控制台**（设置 → 游戏设置 → 启用开发者控制台），按 `~` 打开，
   把 `console_csgo_setup.txt` 里"easy mode"那段命令粘贴执行（关键几条）：

   ```
   sv_cheats 1; sv_pausable 1; mp_roundtime 6000; bot_kick;
   bot_difficulty 0; sv_auto_adjust_bot_difficulty 0; sv_infinite_ammo 1; fps_max 64;
   mp_restartgame 1;
   bot_add ct easy;   （重复若干次，添加够 bot）
   ```

   `sv_cheats 1` 是必须的——`dm_run_agent.py` 启动时会自动在控制台输入
   `mp_restartgame 1` 和 `give weapon_ak47` 来重开局/补枪，没有 cheats 权限会失败。
4. 确认游戏设置符合 4.3 节（尤其是 **1024×768 窗口化 + 灵敏度 2.50 + Raw Input 关**）。

### 第 5 步：运行

```bash
conda activate e2e
python dm_run_agent.py
```

启动后脚本会：找到游戏窗口 → 记录当前鼠标位置为"屏幕中心" → 自动重开局并给 AK47
（通过模拟按键在控制台打字实现）→ 开始 16fps 循环推理。**此时不要动键鼠。**

- 想看 AI 的"视野"和决策（鼠标向量、开枪概率、按键状态叠加在画面上）：
  在脚本中把 `IS_DEMO=True`
- 想统计击杀/死亡：配好 GSI 后把 `IS_GSI=True`
- **按 Q 退出**（脚本会自动松开所有按键）

控制台输出示例（每 1000 帧刷新一行）：

```
p_d4_dmexpert_28 it 0 /1 , n 12000 , ds 8.53 , ks 23.1 , fwd 0.031 , ms 0.058 , inaction 0
                                    ↑每千帧死亡  ↑每千帧击杀  ↑前向传播耗时(s)  ↑本帧总耗时
```

成绩同时被追加保存到脚本目录的 `rewards_.p`（pickle 文件），可用 Python 读取对比多次实验。

> 💡 实时观看时鼠标动作会显得"一顿一顿"——这是正常的，agent 每秒只更新 16 次
> （`IS_SPLIT_MOUSE=True` 时每帧分两次位移，稍平滑些）。

## 6. 路线 B：用官方数据集训练自己的模型

**目标：** 不自己录数据，用作者公开的数据集复现训练。数据同样在
[HuggingFace 数据集页](https://huggingface.co/datasets/TeaPearce/CounterStrike_Deathmatch)：

| 数据集 | 规模 | 说明 |
|---|---|---|
| `dataset_dm_scraped_dust2_tars/` | 5500 文件 / **~700GB** | dust2 死斗，网上服务器旁观抓取（预训练用） |
| `dataset_dm_expert_dust2/` | 190 文件 / 24GB | dust2 死斗，**作者亲手打的干净数据**（微调用，新手推荐从这开始） |
| `dataset_aim_expert/` | 45 文件 / 6GB | aim 练枪图专家数据（练枪法） |
| `dataset_dm_expert_othermaps/` | nuke/mirage/inferno 各 10 文件 | 其他地图专家数据 |
| `dataset_metadata/` | ~6GB | 各数据集对应的元数据 `.npy`（子采样时需要） |

> 每个 `.hdf5` = 1000 帧 ≈ 1 分钟游戏（格式见[第 8 节](#8-数据格式详解)）。

### 操作步骤

1. **下载数据**（推荐先只下 `dataset_dm_expert_dust2` 试试水，24GB）
2. **改 `dm_train_model.py` 头部配置**（约 30~60 行）：

   ```python
   batch_size = 1            # 总 batch；单卡就保持 1（序列很长，显存占用大）
   l_rate = 0.0001

   file_name_stub = 'dm_july2021_expert_'      # 数据文件名前缀（与你下载的数据集对应）
   folder_name = 'D:/csgo_data/expert/'        # ← 改成你的数据存放目录（注意正斜杠）
   starting_num = 1
   highest_num = 30                            # ← 改成你实际下载的文件数

   model_name = 'my_first_model_'              # 你的模型名（名字里的关键词会改变结构！见 9.3）
   save_dir = 'D:/csgo_models/'                # 模型保存目录

   IS_LOAD_WEIGHTS_AND_MODEL = False           # True=从 checkpoint 续训
   IS_SUBSELECT = False                        # True=按武器/击杀事件筛选数据段（需下 metadata）
   ```

3. **多 GPU 问题**：脚本默认 `tf.distribute.MirroredStrategy(["GPU:0"])`，单卡没问题；
   顶部 `os.environ["CUDA_VISIBLE_DEVICES"]="0"` 选择用哪块卡。
4. **训练**：

   ```bash
   python dm_train_model.py
   ```

   训练细节（代码里已实现，了解即可）：
   - 从每个 `.hdf5` 抽取 96 帧序列，起点随机向后抖动最多 20 帧（`N_JITTER`）
   - 每个样本做亮度（0.7~1.3）/对比度增强；镜像翻转默认关（`IS_MIRROR`，对死斗无效、对 aim 图有效）
   - 鼠标最极端两档（±1000/±200）会被重映射到相邻档（防极端值）；开枪序列的空隙会被填平（弹匣连发间隙）
   - 每跑完一个 epoch 就存一次 checkpoint（`tp_save_model` 存 `.json` 结构 + `.h5` 权重
     + `_opt.pkl` 优化器状态 + `.p` 超参数字典）
   - 数据加载用 `DataGenerator(keras.utils.Sequence)`，从 hdf5 流式读取，不会把 700GB 读进内存

5. **转 stateful**：训练完，改 `tools_create_stateful.py` 顶部的 `save_dir` 和
   `model_names = ['你的模型名']`，运行：

   ```bash
   python tools_create_stateful.py
   ```

   生成的 `<模型名>_stateful.json/.h5` 放进 `model/` 文件夹，按[路线 A 第 5 步](#第-5-步运行)运行。

## 7. 路线 C：完整流程——从录制数据到部署

**目标：** 自己采集训练数据，走通论文全流程。工程量较大，适合想深入研究的读者。

### 7.1 录制数据（二选一）

**方式一：`dm_record_data.py`（旁观抓取，论文主数据来源）**

原理：进入服务器观战，脚本每帧抓取"当前观战对象的截图 + 元数据"（血量/弹药/位置/速度/视角，
同时从**游戏内存**和 **GSI** 两个渠道读，方便交叉验证）。它还会：
- 自动在控制台输入 `spectate`，按空格切到第一人称观战视角
- 每 200 帧或观战对象死亡时按 `1` 切换到**当前最高分玩家**
- 每 1000 帧存一个 `.npy` 文件（约 1 分钟数据）

使用前修改脚本头部：

```python
save_name = 'dm_mydata_'                        # 输出文件名前缀
folder_name = 'D:/csgo_data/recorded/'          # 输出目录（必须已存在）
```

前置条件：游戏运行中、已配好 GSI（见 4.5）、能联网（脚本启动时自动从 hazedumper 更新内存偏移）、
管理员权限运行（读其他进程内存需要）。

**方式二：`dm_record_data_me_wasd.py`（自己玩，数据质量最高）**

自己打 bot/死斗，脚本同时录制。关键点：**你必须用改过的键位玩**——
用 **T/F/G/H** 代替 W/A/S/D、**U** 代替 R（换弹）、**M** 代替空格（跳），
这样脚本可以直接读键盘状态拿到"干净"动作（否则要靠反推）。记得先在游戏设置里
解绑这些键。左键开枪直接读鼠标状态，无需改键。

### 7.2 动作推断（`dm_infer_actions.py`）

旁观录制的 `.npy` 只有元数据没有操作，此脚本用"逆动力学"反推：

- **鼠标移动** ≈ 前后帧视角角度变化（`viewangle_xy` / `viewangle_vert` 的差分）
- **WASD** ≈ 速度向量方向/大小的变化模式
- **开枪** ≈ 弹药数减少

同时输出数据质量统计，**按提示删掉坏文件**：

- `ram_gsi_disagree_hp/ammo` 高 → 内存和 GSI 读数对不上，说明数据不可靠
- `vel_static` 高 → 观战对象长时间不动（可能在挂机）
- 死亡/加载帧会被跳过不打标

修改头部 `file_name_stub` / `folder_name` 指向你的数据后运行。输出追加为
`.npy` 中的第三列 → `[img_small, curr_vars, infer_actions]`。脚本可重复运行覆盖旧标注。

## 8. 数据格式详解

### 8.1 `.npy` 文件（录制原始数据）

`np.save` 的对象是长度 1000 的列表，第 `i` 项：

```
[img_small, curr_vars, infer_actions, y_train, x_aux, helper_arr]
   ↑          ↑            ↑              ↑        ↑        ↑
 150×280×3  元数据字典    反推动作        onehot   辅助输入  [击杀,死亡]
 BGR uint8  (见下)       (7.2 节)        动作标签  (未启用)  二元标志
```

> 前三列是录制+推断阶段写入；后三列由 `dm_pretrain_process.py` 追加。

`curr_vars` 字典常用键：

| 键 | 含义 |
|---|---|
| `obs_mode` | 观战模式（4=第一人称观战） |
| `obs_health` / `gsi_health` | 血量（内存读 / GSI 读，两边可交叉验证） |
| `ammo_active` / `gsi_ammo` | 当前武器弹匣弹药 |
| `gsi_kills` / `gsi_deaths` | 击杀/死亡数（用于生成击杀事件标签） |
| `gsi_team` | 阵营 'CT' / 'T' |
| `localpos1/2/3` | 玩家 x/y/z 坐标（地图覆盖分析用） |
| `vel_1/2/3`, `vel_mag`, `vel_theta_abs` | 速度分量、模长、相对朝向的角度 |
| `viewangle_xy` / `viewangle_vert` | 水平/垂直视角（推断鼠标移动的关键） |
| `itemdef` | 当前武器定义索引 |

### 8.2 `.hdf5` 文件（训练数据，每文件 1000 帧）

以帧号 `i`（0~999）为 key：

| Key | 内容 |
|---|---|
| `frame_i_x` | 截图（150×280×3） |
| `frame_i_y` | onehot 动作标签，52 维拼接：`[11键 + 1左键 + 1右键 + 23鼠标X + 15鼠标Y]` |
| `frame_i_xaux` | 辅助输入（历史动作+血量弹药阵营）——**最终版 agent 未使用** |
| `frame_i_helperarr` | `[kill_flag, death_flag]`，如 `[1,0]` = 这帧击杀且未死 |

选 hdf5 是为了**不用整个读入文件就能随机取一段帧序列**（700GB 数据没法全进内存）。

## 9. 模型结构与动作空间（技术细节）

对照 `NN_overview.png` 食用。

### 9.1 网络结构（`dm_train_model.py`）

```
输入 (96, 150, 280, 3)  连续96帧，像素值0~255，未归一化
   ↓  TimeDistributed
EfficientNetB0 (ImageNet 预训练, 取第161层特征图)   ← 逐帧特征提取
   ↓  TimeDistributed(Flatten)
ConvLSTM2D(256 filters, 3×3 kernel, dropout 0.5)   ← 时序记忆（模型名含 'big' 则512，含 'extra' 则再来一层）
   ↓  (模型名含 'LSTM' 时再加一层 LSTM(256))
四个并行输出头 + 价值头：
   ├─ Dense(11, sigmoid)   键盘 11 键
   ├─ Dense(2,  sigmoid)   鼠标左/右键
   ├─ Dense(23, softmax)   鼠标 X 位移档位
   ├─ Dense(15, softmax)   鼠标 Y 位移档位
   └─ Dense(1,  linear)    价值函数 V(s)（critic）
```

- 训练时 `batch_size=1`、Adam lr=1e-4、自定义损失 = 各头 BCE/交叉熵 + critic 损失
  `10·MSE(r_t + γ·V_{t+1} − V_t)`，γ=0.995（config.py `GAMMA`）
- 奖励函数（数据生成器内实现）：`r = 击杀 − 0.5×死亡 − 0.01×开枪`
  （鼓励多杀少死，轻微抑制乱开枪）

### 9.2 动作空间（`config.py`）

| 分量 | 维度 | 取值 |
|---|---|---|
| 键盘 | 11 | `w a s d space ctrl shift 1 2 3 r`（多标签，可同时按） |
| 鼠标左/右键 | 2 | 0/1 |
| 鼠标 X | 23 档 | -1000, -500, -300, -200, -100, -60, -30, -20, -10, -4, -2, 0, 2, 4, 10, 20, 30, 60, 100, 200, 300, 500, 1000 |
| 鼠标 Y | 15 档 | -200, -100, -50, -20, -10, -4, -2, 0, 2, 4, 10, 20, 50, 100, 200 |
| 价值头 | 1 | 连续值 |

鼠标档位单位是"每帧（1/16 秒）SendInput 发送的位移量"，非对称分布——人类大多数时刻
鼠标几乎不动（0 附近档位最密集），大幅甩枪是少数。**推理时**（`onehot_to_actions`）：
键盘取阈值 0.5 的多标签、鼠标 X/Y 取 softmax 的 argmax。

### 9.3 模型命名暗号（重要！）

代码**根据模型名字符串决定网络结构**（训练和转 stateful 时都生效）：

| 名字包含 | 结构变化 |
|---|---|
| `drop` | ConvLSTM2D 开 dropout 0.5 |
| `big` | ConvLSTM2D 512 filters（默认 256） |
| `extra` | 额外加一层 ConvLSTM2D(256) |
| `LSTM` | Flatten 后加 LSTM(256) |
| `randinit` | EfficientNetB0 不加载 ImageNet 权重（随机初始化） |
| `lowres` | 输入先缩放到 100×187（仅 stateful 转换逻辑里处理） |

例：`ak47_sub_55k_drop_d4` → 带 dropout 的标准结构。**自己命名模型时保持一致，否则结构对不上权重会报错。**

### 9.4 stateful vs non-stateful（Keras 冷知识）

- **训练**用 non-stateful：每个 batch（96 帧序列）内部记忆，batch 间自动重置
- **推理**必须用 stateful：一次只喂 1 帧，LSTM 隐状态跨帧保留（否则 AI 每帧都"失忆"）
- Keras 无法直接切换，所以 `tools_create_stateful.py` 重建一个 `stateful=True` 的孪生网络
  再逐层拷贝权重。推理时偶尔会 `model_run.reset_states()` 清记忆（卡死自救）

## 10. 常见问题排查（FAQ）

整理自 README Troubleshooting（致谢 Mert Can Çakmak），按命中率排序：

**Q1：脚本报错找不到游戏窗口 / `CSGO wasnt found`**
窗口标题会随版本变化。`dm_run_agent.py` 用的标题是
`'Counter-Strike: Global Offensive - Direct3d 9'`（2022 年 2 月后），
录制脚本用 `'counter-Strike: Global Offensive'`。FindWindow 不区分大小写，
但 `- Direct3d 9` 后缀要匹配你当前窗口标题，可自行打印调整：
```python
hwin_csgo = win32gui.FindWindow(None, 'Counter-Strike: Global Offensive - Direct3D 9')
```

**Q2：想确认截屏是否正常**
直接运行 `python screen_input.py`，会弹窗显示抓到的 150×280 小图（放大 800 宽显示），
按 Q 退出。截图应含完整游戏画面（HUD 顶栏和天空一部分被裁掉是**正常**的）。

**Q3：AI 不动 / 乱转 / 不开枪**
按顺序排查：
1. 游戏设置是否严格匹配 4.3 节（**灵敏度 2.5 + Raw Input 关 + 1024×768 窗口化** 最致命）
2. 用硬编码动作测试管道：在 `dm_run_agent.py` 里把 `mouse_x_smooth` 设为小常数——AI 该原地转圈；
   再测 `Lclicks=1`（该开枪）、`keys_pressed=['w']`（该前进）。能转/开枪/前进 = 输出端正常，问题在模型输入端
3. `IS_DEMO=True` 看 AI 收到的画面和各项概率输出
4. 检查帧率够不够 16fps：取消 `config.py` 里
   `print('arrived later than wanted to :/, took ...')` 的注释，若频繁超时说明 GPU/机器太慢
5. 游戏限帧释放资源：控制台 `fps_max 64`
6. 有用户反馈需在 `dm_run_agent.py` 顶部加：
   ```python
   import win32com.client
   shell = win32com.client.Dispatch("WScript.Shell")
   shell.SendKeys('%')
   ```
   （解决焦点问题，让模拟按键能送达游戏窗口）

**Q4：模型加载了但预测结果"不对劲"**
Python 3.9 + TF 2.4.5 加载旧模型会产生**不同预测**（模型加载方式差异所致）。
请用 Python 3.6.8/3.6.9 + TF 2.3.0。

**Q5：录制脚本报错 / 读内存全是 0**
- 用管理员身份运行终端/IDE
- 确认 hazedumper 偏移与游戏版本匹配（脚本开头会自动拉取最新 csgo.toml；
  若断网需手动更新 `dm_hazedumper_offsets.py`）
- GSI 未配置会导致 `map not in keys` 一直等待——看 4.5 节

**Q6：`dm_train_model.py` 报找不到文件 / KeyError**
检查 `file_name_stub` 和 `folder_name` 是否与你数据集的实际文件名前缀、路径完全一致
（hdf5 文件名是 `hdf5_` + stub + 编号）。`IS_SUBSELECT=True` 还需要额外下载
`dataset_metadata/` 并配好 `curr_vars_folder` / `curr_vars_stub`。

**Q7：训练时显存爆了**
`batch_size` 已经是 1 了；可尝试减小 `N_TIMESTEPS`（但与预训练模型不兼容）、
用更小的自定义结构，或换更大显存的卡。原作者是在多 GPU 服务器上训练的。

**Q8：AI 眼里鼠标"很卡"**
正常。16fps 控制频率所限（`IS_SPLIT_MOUSE=True` 可让鼠标每帧分两次动，观感稍好）。

**Q9：Windows 上能训练吗？**
`dm_train_model.py` 本身不依赖 win32（训练相关 import 无 Windows 限制），
作者在 Linux 多卡机器上跑，但单卡 Windows 修改路径后理论上可用。
反过来，**录制/运行脚本绝不能在 Linux 跑**（win32 API + SendInput）。
